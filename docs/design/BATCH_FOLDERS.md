# 批量管理文件夹：参考产品和结论

状态：2026-11-26 用户已确认；已实现（分支 feat/batch-folders）。用户的三点决定：
1. 文件夹支持创建副本。
2. 所选含文件夹时，删除确认加「包括其中的 M 篇文档」；单个删除文件夹的确认也一起改。
3. 创建副本改成后台任务，这次一起做。

## 现状

- 批量管理从顶层文件夹的「…」或文件夹页顶栏进入，范围是这个顶层文件夹内（5ad83bda），最多选 50 项。
- 底层已经按「文件夹连同内容」处理：`move_docs` 走后台写入队列（`tree_writes.rs`），跳过移进自身子树的项，移动对话框里也不显示所选项的子树；`delete_docs` 把每个最上层的所选项连同子树作为一项放进回收站，先在界面上移走，写完以列表回读为准；`copy_doc` 遇到文件夹会调 `copy_folder` 整个复制。撤销各是一步（「移动」「删除」「批量创建副本」）。
- 缺的是界面：文件夹页宫格里的文件夹卡片在批量模式下整张变灰（`opacity 0.45`），没有勾选框、点了没反应。列表视图和侧栏的文件夹行已经能勾选，但没人测过。

## 参考产品

| 产品 | 多选里能选文件夹吗 | 对文件夹能做的批量操作 |
|---|---|---|
| 访达 | 能，和文件一样 | 拷贝/复制（整个文件夹）、移到废纸篓、拖动移动、压缩；移进自身时报「不能移到自己里面」 |
| 备忘录 | 文件夹不进笔记多选 | 只能一个个删、移文件夹；删除文件夹时提示「其中的 N 条笔记也会删除」 |
| Notion | 能（页面即文件夹） | 移动、删除、复制，子页一起；选了父页和子页时以父页为准 |
| 飞书云文档 | 能 | 移动、删除、创建副本（文件夹不支持副本，只对文档）、下载（文件夹不可） |
| Google Drive | 能 | 移动、移到回收站、下载（打包）；「复制」对文件夹不可用 |

共同点：移动、删除对文件夹和文档一视同仁；副本和导出各家不一。（表里是按各产品现行版本的印象整理，没有逐一实测。）

## 结论

### 批量选中文件夹时能做的事

| 操作 | 文件夹 | 理由 |
|---|---|---|
| 移动到 | 能 | 各家都有；后台队列和链接改写已经支持 |
| 删除（进回收站） | 能 | 各家都有；整个文件夹作为一项进回收站，可整体恢复 |
| 创建副本 | 能 | 访达、Notion 能；本地文件夹就是目录，复制很自然，单项的 `copy_folder` 已有。副本名「X 副本」，放在原处 |
| 置顶 | 不加 | 单项菜单里文件夹本来就不能置顶；批量栏现在也没有置顶 |
| 导出 | 不加 | 批量栏现在没有导出，文件夹单项也没有；以后做「导出为 Markdown 压缩包」时再统一加 |

### 混选文件夹和文档

三个操作（副本、移动到、删除）对两者都可用，所以混选时**没有要变灰的按钮**。只有两条规则：

- **上层优先**：所选项里有一项在另一个所选文件夹里面（只会出现在侧栏的树里），操作时只算外层的那个。删除已经这样做；移动和副本也照做，否则副本会复制两份、移动会把里面的那篇拽出来。参考 Notion。
- 「全选」包括当前层的文件夹和文档；侧栏里是这个顶层文件夹内的所有行，仍受 50 项上限。一个文件夹算一项，不按里面的文档数算。

### 边界

1. **移进自身或子文件夹**：移动对话框里不显示所选文件夹及其子树（已有），所以选不到；`move_docs` 再过滤一次兜底。全部被过滤时提示「不能移到所选文件夹里面」，不弹「移动成功」。
2. **删除确认**：沿用现在的确认框（标题「是否删除所选的 N 项？」，正文「删除的内容将进入回收站，30 天后自动彻底删除」）。所选含文件夹时，正文前面加一句「包括其中的 M 篇文档」，M 是所有所选文件夹里的文档总数，参考备忘录。单个删除文件夹的确认也加这一句，保持一致。不另设阈值：数字写清楚就够了，且都能撤销、能从回收站恢复。
3. **顶层文件夹**：批量范围本来就在一个顶层文件夹内部，顶层文件夹自己是分组标题，**不能选**（`in_batch_scope` 已排除）。它的「从侧栏移除」留在单项菜单里，不进批量。
4. **撤销**：批量移动、删除、副本各记一步文件历史，⌘Z 一次全部复原（文件夹连同里面的文档、图片、链接）。照现在批量处理文档的做法，不新加机制；补单元测试确认文件夹也能完整复原。
5. **打开中的文档**：所选文件夹里有正在编辑的文档时，删除照现有规则（先保存；别的窗口开着就提示先关掉）；移动后编辑器跟到新位置（写入队列已处理）。
6. **链接和图片**：文件夹移动时改写跨边界的相对链接，走 `Store` 里现有的 relocate 逻辑（写入队列调的就是它）；补测试确认批量移动文件夹后链接、图片都能打开。

### 界面

- 宫格里的文件夹卡片：批量模式下不再变灰；左上角放和文档卡片同样的勾选框；点卡片勾选，不打开；选中后和文档卡片一样（勾选框选中，卡片不另加底色）。悬停的「+」「…」照旧隐藏。
- 列表视图、侧栏：文件夹行和文档行一样勾选（现有代码已支持，补测试）。
- 顶栏不改布局（design-lane 在调对齐），只是按钮对文件夹也生效。

### 写入

- 移动：现有后台写入队列，先在界面生效，失败回滚并提示（不变）。
- 删除：现有后台删除任务，先在界面移走，写完以回读的列表为准，失败的回来并提示（不变）。
- 副本：现在在界面线程上同步复制，大文件夹会卡住。改成和删除一样的后台任务：复制期间界面不卡，复制完以回读的列表为准、新行出现，失败提示；仍记一步撤销。

## 不做

- 批量重命名、批量置顶、批量导出、批量拖动（拖动多选另议）。
- 跨顶层文件夹的批量（范围已限定在一个顶层文件夹内）。

## 已做的补充（2026-11-26）

- 文件夹的单项菜单（右键和「…」）也有「创建副本」，和文档一样走后台副本任务，复制完打开副本。
- 批量模式下文档卡片的勾选框放在标题第一行，标题右移让位，不再压住首字。

## 后续

- 副本里的链接仍然指向原件（复制整个文件夹时，文件夹内部互相引用的链接没有改成指向副本）。要不要改、怎么改另议。
